# Deployment Guide

This guide covers two things: (1) hosting CloudDeploy Hub itself on free tiers (Supabase + Render +
Vercel), and (2) deploying *your* applications with it.

## Part 1: Host CloudDeploy Hub

### 1. Supabase (database)

1. Create a project at [supabase.com](https://supabase.com).
2. **Connect** → copy the **Transaction pooler** connection string (port `6543`), e.g.
   `postgresql://postgres.<ref>:<password>@aws-0-<region>.pooler.supabase.com:6543/postgres`.
3. That's all. Tables are created automatically on the backend's first start. CloudDeploy Hub switches
   the URL to the `psycopg` driver, adds `sslmode=require` and disables prepared statements, which the
   transaction pooler requires.

### 2. Render (backend API)

1. Render dashboard → **New → Blueprint** → pick this repository. `render.yaml` defines a free
   Python web service `clouddeploy-hub-api` (health check `/api/health`).
2. Fill in the prompted environment variables:

| Variable | Value |
|---|---|
| `DATABASE_URL` | Supabase transaction pooler URI |
| `FRONTEND_URL` | Your Vercel URL, e.g. `https://clouddeploy-hub.vercel.app` |
| `BACKEND_URL` | This service's URL, e.g. `https://clouddeploy-hub-api.onrender.com` |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | From Google Cloud (step 4) |
| `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET` | From the GitHub OAuth App (step 5) |
| `RENDER_API_KEY`, `VERCEL_TOKEN`, `NETLIFY_AUTH_TOKEN`, `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` | Provider tokens (only the ones you want to enable) |
| `CORS_ORIGIN_REGEX` | Optional: allow Vercel preview URLs |

`SECRET_KEY` is generated by Render. Keep it: it encrypts stored GitHub tokens and deployment
environment variables. **Never set `DEV_LOGIN` in production.**

> Render's free instance sleeps when idle and its disk is temporary. CloudDeploy Hub keeps all state
> in Supabase (including uploaded projects), and on wake-up it resumes watching any deployment that
> was in progress.

### 3. Vercel (frontend)

1. Vercel → **Add New → Project** → import this repository.
2. **Root Directory:** `frontend` (framework is detected as Vite; `vercel.json` adds SPA rewrites).
3. Environment variable: `VITE_API_URL` = your Render backend URL.
4. Deploy, then put the Vercel URL into Render's `FRONTEND_URL`.

### 4. Google sign-in

Google Cloud Console → APIs & Services → **Credentials** → Create **OAuth client ID** (Web application).

- Authorized JavaScript origin: your Vercel URL
- Authorized redirect URI: `https://<render-backend>/api/auth/google/callback`
- OAuth consent screen: scopes `openid`, `email`, `profile`

### 5. GitHub OAuth App

GitHub → Settings → Developer settings → **OAuth Apps** → New.

- Homepage URL: your Vercel URL
- Authorization callback URL: `https://<render-backend>/api/github/oauth/callback`

## Part 2: Deploy your application

1. **Sign in** with Google.
2. **GitHub** page: enter your username (identity only) and select **Connect GitHub** to authorize.
3. **Add Project**: pick a repository and branch, or upload a folder or `.zip`.
4. Review **Project Analysis** (set a root directory for monorepos).
5. **Choose Platform**: only compatible platforms are selectable.
6. Adjust settings, read the **Deployment Preview** (including any generated Dockerfile, workflow
   or `netlify.toml`), and select **Deploy Now**.
7. Watch **Deployment Progress**: status and logs come from the provider. When the URL passes its
   health check the deployment shows **LIVE** with the real URL.

Uploaded projects can be deployed directly to Vercel and Netlify. Render, GitHub Pages and
Cloudflare Pages need a repository: use **Publish Project to GitHub** first.
